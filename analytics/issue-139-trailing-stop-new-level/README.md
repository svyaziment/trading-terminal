# Issue #139 — ступенчатый трейлинг-стоп на `test_20260830_new_level` (симулятор 50k)

A/B-анализ в портфельном симуляторе (депозит 50 000 RUB, слот 10k, максимум 5
позиций, приоритет по объёму, GAME OVER при cash ≤ 0): запертая стратегия
`test_20260830_new_level` (id=126) с фиксированным выходом стоп/тейк 1:3 (**A**)
против той же конфигурации входа со ступенчатым трейлинг-стопом (**B**).
**Единственное различие A и B — трейлинг-стоп**; вход, начальный риск 1R,
комиссия и вселенная идентичны.

Методика слот-реплея унаследована от `analytics/issue-130-sr-support-portfolio/`
(правила Issue #44). Тот же движок входа — единый `StrategyEvaluator` (тот же
«мозг», что и в бою).

## Таблица ступеней (в R от входа)

| Цена | Действие |
|---|---|
| 0 | Вход; стоп −1R, тейк +3R (уровень сопротивления) |
| +2R | стоп → +1.5R |
| +2.5R | стоп → +2R |
| +3R | выход по тейку |

Ступени задаются в `trailing.py` (`DEFAULT_STEPS`) в единицах R, а не в % от
входа. Тейк не меняется — трейлинг только поджимает стоп на поздней фазе.

## Модель заполнения (без заглядывания в будущее)

Совпадает с `StrategyEvaluator.on_bar`: в пределах одного бара сначала
проверяется стоп (`low <= stop`), затем тейк (`high >= take`). Ступень,
взведённая максимумом **текущего** бара, поднимает стоп только для
**следующих** баров — бар не может одновременно взвести стоп своим high и
быть выбитым этим же поднятым стопом по своему low.

## Как получены оба исхода

`extract_inputs.py` прогоняет единый «мозг» по 1-мин свечам за полный период,
воспроизводя каждый вход/выход боевого бэктеста, и на **одном и том же**
intra-trade пути каждой сделки считает и A, и B. Проверка
`baseline_replay_mismatches` подтверждает, что воспроизведённый A совпадает с
исходной сделкой движка (допуск по процентам). Пути цен в `results.json` не
складываются — наружу уходят только компактные исходы A/B на сделку, поэтому
`analysis.py` работает **без БД**.

## Состав

| Файл | Назначение |
|---|---|
| `trailing.py` | Конфигурируемые ступени в R + режим выхода (аналитический, не боевой) |
| `extract_inputs.py` | Снимок кандидатов и обоих исходов A/B из БД (только чтение) |
| `analysis.py` | Портфельный слот-реплей A/B, метрики, графики, `summary.json` / `report.md` (без БД) |
| `inputs.json` | Снимок входных данных (конфиг id=126, SHA, вселенная, ступени, флаги) |
| `results.json` | Сделка-за-сделкой: вход + исход A + исход B |
| `summary.json` | Итоговые метрики A/B и вердикт |
| `report.md` | Отчёт (RU + EN) с рекомендацией и цифрами |
| `plots/*.png` | Equity A/B, распределение закрытий по типу выхода |

## Запуск

Из корня репозитория.

Снимок из БД (один раз, полный период, ~28 тикеров):

```bash
python analytics/issue-139-trailing-stop-new-level/extract_inputs.py --workers 4
```

Смоук на части тикеров (без записи `results.json`):

```bash
python analytics/issue-139-trailing-stop-new-level/extract_inputs.py --tickers SBER GAZP
```

Сравнение и публикация (без БД, нужен `results.json`):

```bash
python analytics/issue-139-trailing-stop-new-level/analysis.py
```

Другая сетка ступеней (в R), например +3→+2, +4→+3:

```bash
python analytics/issue-139-trailing-stop-new-level/extract_inputs.py --step 3:2 --step 4:3
```

Юнит-тесты (без БД и сети):

```bash
cd backend && python -m pytest -q tests/test_issue139_analysis.py
```
