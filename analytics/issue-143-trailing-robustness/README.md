# Issue #143 — робастность ступенчатого трейлинг-стопа к уровням сетки (эпик #142)

Оверлей-решётка поверх книги #139: 28 тикеров MOEX, 3 305 сигналов, 3 118 сделок базовой
сетки, 5 многоступенчатых сеток трейлинга, стресс комиссией и проскальзыванием, walk-forward по
9 скользящим окнам. Доступ к PostgreSQL только `SELECT`; защищённая конфигурация
`strategies` (id=126, флаги 36/102/118) не читается на запись и не изменяется.

## Состав каталога

| Файл | Назначение |

| `run.py` | конвейер `extract → analyze → report` (стадии через `--stage`) |

## Запуск

Из корня репозитория (PowerShell):

```powershell
$env:PYTHONIOENCODING = "utf-8"
python analytics/issue-143-trailing-robustness/run.py --stage all
```

На готовом кэше полный цикл занимает ~2 минуты и перезаписывает артефакты в этом
каталоге (156.73 с — стадия анализа, она попадает в `summary.json.elapsed_sec`; 160.62 с —
полное время процесса — в протоколе `run.md`). Отладочные прогоны (`--tickers`, `--limit`,
`--out-dir out_debug`) пишут в отдельный каталог и не должны попадать в коммит. Лог прогона — в
`reports/Vulpec/143_trailing-robustness/` (вне индекса, как требует постановка).

Воспроизводимость отчёта: `--stage report` собирает `report.md`, `run.md` и `summary.json` из
`report.json.gz` — без БД и без пересчёта решётки. Проверено в изолированном worktree из
закоммиченного состояния (без `cache/`, ~1.6 с): `report.md` и `summary.json` сошлись
байт-в-байт с опубликованными, `report.json.gz` — по всем значениям (различается только
gzip-заголовок со временем создания), а `run.md` как протокол закономерно отличается временем,
стадией и длительностью. В отладочном прогоне с `--out-dir` к этому добавляются только строки
с путями артефактов (§1 и §14, они рендерятся относительно выбранного каталога) — 10 строк в
`report.md` и 9 в `summary.json`; метрики и выводы совпадают построчно.

## Итог этого прогона

Паритет базовой сетки `ref139` с книгой #139 подтверждён: сверено 3 305 сделок, расхождений
по механике выхода 0, капитал 103 216 ₽ против 103 176 ₽ у #139 (в допуске 0,20 %).
Разброс итогового капитала по пяти сеткам — 12 742 ₽: лучшая `two_step_aggressive`
108 569 ₽, худшая `three_step_steady` 95 827 ₽; по composite-баллу устойчивости лидирует
`ref139` (47,3 из 100). Все пять сеток прибыльны в 9/9 walk-forward-окнах; «game over» по
издержкам не зафиксирован, но при комиссии 0,15 % и проскальзывании 20 б.п. капитал
базовой сетки падает до 16 708 ₽. Худшая сетка относительно контрольной
(stakeholder-тест) — `three_step_steady` (Δequity −525 ₽). Решение о дефолтной сетке — за
Product Owner (#144): аналитика дефолт не назначает. Ранжирование по composite score
опирается на абсолютную просадку и сходимость причин выхода: компоненты стресс-капитала,
деградации DD и walk-forward в этом прогоне одинаковы у всех сеток (см. §4 отчёта).
Согласованность сеток: у 80.5 % сделок исход одинаков во всех пяти сетках, медианный ρ Спирмена
по парам 0.86 при минимуме 0.7497 (§8); причина выхода относительно базовой сетки меняется у
1 112 сделок из 3 305, материальных (|ΔPnL| > 20 ₽) — 1 057, и новой причиной чаще всего становится
`trailing` — 784 (§7).
Издержки давят на капитал почти целиком комиссией и не меняют механику: доля trailing-выходов
базовой сетки держится 36.8–36.9 % во всех 12 её стресс-прогонах, по всем 60 прогонам решётки
разброс 29.7–47.2 % (§5). Walk-forward даёт устойчивый знак (9/9 окон), но не уровень:
минимальное PnL окна базовой сетки (+745 ₽) сопоставимо с одним слабым месяцем книги (§6).
Полные ограничения прогона — §13 отчёта.
