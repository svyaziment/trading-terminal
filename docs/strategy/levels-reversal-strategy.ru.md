# Стратегия «Уровни + подтверждение разворота»

> Статус: валидирована на SBER/GAZP/VTBR (2 года истории). Продакшн-мозг: `StrategyEvaluator.check_entry`. Прототип: `backend/app/analytics/levels_backtest.py`.
> Last refreshed: 2026-08-30 (задача #127 levels_sr_support — только поддержка с трекером).

## 1. Обзор

Долгосрочная (medium-term) rule-based стратегия только в лонг для голубых фишек MOEX. Суть: **вход у уровня поддержки только после подтверждения разворота на старшем таймфрейме**, выход на ближайшем сопротивлении (тейк) или ниже поддержки (стоп). Симуляция на минутных свечах для точного контроля входа/выхода, при этом структура (уровни, сигналы) берётся с 4h.

Это первая стратегия в проекте, **прибыльная после комиссии и проскальзывания на out-of-sample тикерах** (GAZP, VTBR не использовались для подбора параметров — параметры фиксировались на SBER).

## 2. Логика

### 2.1 Уровни поддержки/сопротивления (4h)
- **Swing-уровни:** фракталы на 4h свечах — бар, у которого high/low экстремален относительно `swing_window` баров слева и справа. Кластеризуются в зоны `±zone_atr × ATR(14)`.
- **Уровни по импульсным свечам:** заполненные импульсные свечи (тело/диапазон > 0.7 И |close−open| > 1.5×ATR); open свечи = уровень (зелёная → поддержка, красная → сопротивление).
- **Скользящее окно (без look-ahead):** swing-уровень на баре `i` доступен только с бара `i + swing_window`; импульсный — с бара `i`.
- ATR считается на лету из 4h свечей (не зависит от таблицы `indicators`).

### 2.2 Условия входа (все должны выполняться)
1. **Сигнальный фильтр:** активен 4h BUY-сигнал (`entry_mode`): `levels_ts1` (total_signals ≥ 1) или `levels_ts2` (≥ 2) или `levels_only` (без сигнала).
2. **Цена у поддержки:** close 1min свечи в зоне поддержки `[zone_lower, zone_upper]` или чуть выше (в пределах 0.5×ATR).
3. **Подтверждение разворота** (`confirm_tf`): последняя **закрывшаяся** свеча старшего ТФ (5/10/30 мин) закрылась **выше** зоны поддержки (`close > zone_upper`). Отсекает «пилу» — ложные касания, выбивающие стоп на следующем баре.
4. **Окно входа:** 7:00–19:00 МСК (по часу 1min бара).
5. **Фильтр риск/прибыль** (`risk_reward`, вариант «a»): вход только если `(сопротивление − вход) ≥ risk_reward × (вход − стоп) + комиссия`. `risk_reward = 0` отключает фильтр.
6. **Вето зоны сопротивления** (задача #97): close 1min **не** находится внутри активной зоны сопротивления `[zone_lower, zone_upper]`. Это не role-reversal. Покупка внутри сопротивления при стопе по поддержке в журнале — дефект (ALRS paper #711). `nearest_level_at(..., 'support')` остаётся односторонним; вето — `overlapping_resistance_zone_at` в `levels_engine.py`, вызывается из `StrategyEvaluator.check_entry` (один путь для бэктеста / paper / live).

### 2.3 Условия выхода
- **Стоп:** ближайший уровень поддержки ниже входа; срабатывает по **low** 1min свечи (консервативно, по стопу).
- **Тейк:** ближайший уровень сопротивления выше входа; срабатывает по **high** 1min свечи (по тейку).
- **Ночь/выходные:** позиция держится (без session-only выхода). Голубые фишки, минимальные гэпы/проскальзывание.

### 2.4 Издержки
- **Комиссия:** 0.03% на сторону (0.06% round-trip).
- **Проскальзывание:** `slippage_per_side` применяется к ценам исполнения входа (покупаем дороже) и выхода (продаём дешевле).

## 3. Параметры (настраиваемые)

| Параметр | Значения | Дефолт | Влияние |
|---|---|---|---|
| `swing_window` | 5 / 10 / 15 / 20 | **10** | Окно фракталов для swing-уровней. Меньше = больше (шумных) уровней; больше = меньше (сильных). |
| `zone_atr` | 0.3 / 0.5 / 0.8 | **0.5** | Ширина зоны поддержки/сопротивления в ATR. Шире = больше входов, менее точно. |
| `confirm_tf` | none / 5min / 10min / 30min | **10min** | ТФ свечи подтверждения разворота. `none` = вход по касанию (пила, PF ~0.97). 5/10/30min убирают пилу → PF 1.4–2.0. |
| `risk_reward` | 0.0 / 1.5 / 2.0 | **2.0** | Минимальная прибыль:риск для входа. 0 = без фильтра (больше сделок, ниже PF). 2.0 = строго (меньше сделок, выше PF). |
| `entry_mode` | levels_only / levels_ts1 / levels_ts2 | **levels_ts1** | Сигнальный фильтр. `levels_only` = чистые уровни (PF ~0.5, плохо). `levels_ts1`/`ts2` = + сигнал паттернов (PF ~0.95+). |
| `entry_window_start` / `_end` | 0–23 | **7 / 19** | Окно входа в часах МСК. |
| `slippage_per_side` | 0.0 / 0.0005 / 0.001 | **0.0** | Проскальзывание на сторону. Реалистично для ликвидных: 0.0005 (0.05%). |
| `commission_per_side` | float | **0.0003** | Комиссия на сторону (0.03%). |
| `body_ratio` | float | **0.7** | Порог «заполненности» импульсной свечи (тело/диапазон). |
| `impulse_atr_mult` | float | **1.5** | Порог размера импульсной свечи (× ATR). |

**Рекомендуемый базовый набор:** `swing_window=10, zone_atr=0.5, confirm_tf=10min, risk_reward=2.0 (или 1.5), entry_mode=levels_ts1, slippage=0.0005`.

## 10. Кейс: ALRS paper #711 — вход в зоне сопротивления (задача #97)

**Решение:** гард в `StrategyEvaluator.check_entry`. Вход, чей 1min close лежит в активной зоне сопротивления, отклоняется. Role-reversal («старая поддержка стала сопротивлением, поэтому покупать здесь нормально») **не** является правилом `levels_reversal`. Locked-строка БД `test_20260731` не менялась.

### Сделка

| Поле | Значение |
|---|---|
| `paper_positions.id` | 711 |
| Тикер | ALRS |
| Стратегия | `test_20260731` (`levels_reversal` + `signal_4h_buy`, RR 1:2, confirm 10min) |
| Вход | 2026-08-20 11:50:24 MSK @ **19.80** (market, 5 лотов) |
| Сигнал | `trading.alerts.id = 80`, `signal_source=imbalance`, px 19.79, imbalance 1.40 |
| Стоп / тейк | **19.61** / **20.90** |

| Активный 4h-бар | 2026-08-20 08:00:00 (high 19.95; 4h BUY = `PA_Engulfing`) |

Реконструкция: `build_levels` на `trading.candles_aggregated`, timeframe=4h, `swing_window=10`, `zone_atr=0.5`, импульс 0.7 / 1.5×ATR. ATR активного 4h-бара ≈ 0.5714.

### Уровень, который движок назвал support, формально верен

Импульсная **зелёная** 4h от **2026-07-27 08:00**: O 19.61 / H 20.43 / L 19.61 / C 20.27 (тело/диапазон 0.80, тело 2.09×ATR). По контракту `detect_impulse_levels` зелёная свеча → `type=support`, уровень = open. Бар не является swing high/low. Возраст на входе: **24 дня**.

Зона поддержки: **19.45–19.77**. Fill 19.80 **вне** этой зоны. Он проходит только расширением `zone_upper + 0.5×ATR` (до ~20.05) в `StrategyEvaluator.check_entry`.

### Ценой владело более свежее сопротивление

Ближайший противоположный уровень: импульсное **resistance 19.67** от **2026-08-14 12:00** (open красной 4h). Зона **19.40–19.94** покрывает fill 19.80. Дистанция до сопротивления **0.13** vs **0.19** до выбранной поддержки.

| Уровень | Тип | Метод | Defined | Зона | Дист. от 19.80 |
|---|---|---|---|---|---|
| 19.61 | support | impulse | 2026-07-27 08:00 | 19.45–19.77 | 0.19 |
| 19.67 | resistance | impulse | 2026-08-14 12:00 | 19.40–19.94 | 0.13 |
| 20.90 | resistance | swing | 2026-07-06 08:00 | 20.76–21.04 | 1.10 (тейк) |

Сломанные swing-поддержки 20.00 / 20.01 стоят над рынком (локальный потолок). Внутри дня: хай 19.95 в 11:30, вход на откате 11:50, low бакета 12:00 = 19.58 пробил стоп.

### Почему `check_entry` / `nearest_level_at` пропустили вход

`nearest_level_at(..., 'support')` берёт только `type=support` **ниже** цены. Resistance ниже рынка не становится стопом и **не ветирует** вход, даже если цена внутри его зоны. `nearest_level_at(..., 'resistance')` ищет только **выше** цены, поэтому 19.67 пропускается, а тейк становится 20.90. Старые impulse-уровни не инвалидируются более новым противоположным уровнем рядом. Расширение 0.5×ATR печатает вход «у поддержки», который структурно является покупкой в сопротивление.

Журнал (`support_level=19.61`) и смысл стратегии («вход у поддержки») разошлись. Для `levels_reversal` сделка 711 — **некорректный вход относительно текущей структуры**. Тип 19.61 не баг; баг — отсутствие вето по зоне сопротивления.

### Правило на будущее

Вход в активной зоне resistance при заявленном support — **дефект**, а не «роль развернулась». Гард: `overlapping_resistance_zone_at` в `levels_engine.py`, вызов из `StrategyEvaluator.check_entry` после проверки зоны поддержки (плюс 0.5×ATR). Только нативная зона сопротивления — расширение 0.5×ATR на вето не зеркалится. Фикстура / unit: `backend/tests/test_resistance_zone_veto.py` (`regression_match: true` между `StrategyEvaluator` и `LevelsReversalStrategy` на этой геометрии).

## 11. State machine: пробой и смена роли (задача #106)

Инфраструктура эпика #105. `levels_reversal` по-прежнему **не** считает пробитое сопротивление новой поддержкой для входа. Этот раздел описывает in-memory жизненный цикл, чтобы следующий issue добавил паттерн `level_breakout_retest`.

### Состояния

| Состояние | Смысл |
|---|---|
| `active` | Зона валидна и не пробита (текущая цель вето #97). |
| `broken_up` | Подтверждённое закрытие выше зоны сопротивления. |
| `broken_down` | Подтверждённое закрытие ниже зоны поддержки. |
| `flipped_support` | Пробитое сопротивление удержалось на первом ретесте (close внутри нативной зоны). |
| `flipped_resistance` | Симметрично: пробитая поддержка удержалась на ретесте. |

Переходы: `active → broken_up/down` по правилам пробоя ниже; `broken_up → flipped_support` и `broken_down → flipped_resistance` на первом последующем close внутри `[zone_lower, zone_upper]`. Ложный пробой в этой итерации **не** возвращается в `active`.

### Правила пробоя

Конфиг: `LEVEL_STATE_MACHINE` в `trading_config.py` (не хардкодить). Дефолты: `breakout_buffer_atr=0.25`, `confirm_bars=2`, `min_penetration_atr=0.5`, `zone_extension_atr=0.5`. В `LevelsTracker` подавайте бары того же ТФ, что и уровни (обычно 4h).

Пробой сопротивления (поддержка симметрично ниже `zone_lower`):
1. Последний close `> zone_upper + breakout_buffer_atr × ATR`.
2. Все последние `confirm_bars` close `> zone_upper`.
3. `max(window) >= zone_upper + min_penetration_atr × ATR`.

### Взаимодействие с вето

`overlapping_resistance_zone_at` пропускает строки, у которых `state` не `active`. `build_levels` / `get_levels` колонку `state` не добавляют. Задача #107 передаёт `LevelsTracker` в вето из `StrategyEvaluator`, если включён `level_breakout_retest`, `levels_sr_breakout` или `levels_sr_support` (`is_broken(level_id)`). Locked `test_20260731` не включает ни один, поэтому дефолтный `check_entry` по-прежнему ветирует любое перекрывающееся сопротивление.

## 12. Смена роли: пробой сопротивления + ретест (задача #107)

### Когда срабатывает

1. `LevelsTracker` подтвердил пробой сопротивления (`broken_up`) или первое удержание (`flipped_support`).
2. Цена вернулась в зону ретеста: `level_price ± retest_zone_atr × ATR` (по умолчанию 0.5).
3. Поддержка держит: 1min close ≥ пробитого `level_price`.
4. Окно: `bars_since_breakout` (бары HTF) ≤ `retest_window_bars` (по умолчанию 20).
5. Триггер (если `entry_trigger_bullish=true`): close > предыдущего 1min high либо бычье тело (`body/range > 0.6` из `LEVEL_BREAKOUT_RETEST` в `trading_config.py`).

### Stop / take

`stop = entry − stop_atr × ATR` (по умолчанию 1.0×ATR, ниже зоны ретеста на дефолтной геометрии). `take = entry + risk_reward × (entry − stop)` (по умолчанию 2.0). При включённом паттерне они заменяют levels stop/take.
