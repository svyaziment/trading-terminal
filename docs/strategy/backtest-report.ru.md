# Отчёт о бэктестах: Валидация стратегии торгового терминала

> Последнее обновление: 2026-07-25. Источник: прогоны бэктестов task-049..065, загрузка 1min свечей task-054..063.
> Этот документ описывает методологию бэктестирования, паттерны, стратегии, матрицы, фильтры, бенчмарки, результаты и выводы.

## 1. Обзор

Бэктест-движок валидирует rule-based торговые стратегии на исторических данных акций MOEX. Он детерминирован (одни входные данные → одни выходные), long-only, и учитывает транзакционные издержки.

**Ключевые параметры:**
- Вход: open бара ПОСЛЕ сигнального бара (T+1). Без look-ahead bias.
- Сторона: только LONG. BUY открывает позицию (если нет); SELL — триггер выхода.
- Издержки: комиссия 0.03% на сторону (0.06% round-trip). Slippage моделируется отдельно (по умолчанию 0 тиков).
- Размер позиции: фиксированный 1 лот (v1). Без capital sizing.
- Вселенная: топ-30 акций по объёму (фиксированный срез, selection_bias=true).
- Данные: 1min свечи из MOEX ISS API (2 года для SBER/GAZP/VTBR; ~1 месяц для остальных 27 тикеров из T-Bank API 30min raw).

**Движок:** `backend/app/analytics/backtest_engine.py` + `backtest_models.py`.
**Оркестратор:** `backend/app/api/backtest_jobs.py` (POST /api/backtest/run, GET /api/backtest/run/status, общий лок jobs_state).

## 2. Паттерны (10 всего)

Сигналы генерируются 10 паттернами технического анализа в 5 категориях. Каждый паттерн анализирует индикаторы (RSI, SMA, полосы Боллинджера, объём, формы свечей) и выдаёт BUY или SELL с оценкой уверенности (confidence).

| Категория | Паттерн | Описание | Логика сигнала |
|---|---|---|---|
| Trend | Trend_SMA_Alignment | Выравнивание SMA (20/50/200) | BUY если SMA20 > SMA50 > SMA200 (бычье выравнивание); SELL если наоборот |
| Mean Reversion | MR_RSI_Reversal | Разворот RSI из экстремумов | BUY если RSI пересекает вверх из <30 (перепроданность); SELL если вниз из >70 (перекупленность) |
| Breakout | BO_BB_Squeeze | Сжатие полос Боллинджера | BUY/SELL по направлению пробоя после сжатия волатильности (ширина BB < порога) |
| Volume | VOL_Spike | Всплеск объёма (>2x среднего) | BUY/SELL по направлению движения цены, когда объём > 2× среднего за 20 баров |
| Volume | VOL_Low_Pullback | Откат на низком объёме | BUY если цена откатывается на низком объёме (слабые продавцы) в аптренде |
| Price Action | PA_Hammer | Свеча-молот | BUY если молот появляется после даунтренда (длинная нижняя тень, маленькое тело наверху) |
| Price Action | PA_HangingMan | Свеча-повешенный | SELL если повешенный появляется после аптренда (та же форма, что молот, но на вершине) |
| Price Action | PA_Engulfing | Паттерн поглощения | BUY если бычье поглощение (зелёная свеча > предыдущей красной); SELL если медвежье |
| Price Action | PA_ThreeWhiteSoldiers | Три белых солдата | BUY если 3 последовательные зелёные свечи, каждая закрывается выше (редкий, ~20 сигналов на короткой истории) |
| Price Action | PA_ThreeBlackCrows | Три чёрные вороны | SELL если 3 последовательные красные свечи, каждая закрывается ниже (редкий, ~41 сигнал) |

**Агрегация сигналов:** На каждом баре может сработать несколько паттернов одновременно. Запись сигнала хранит `total_signals` (количество согласных паттернов) и `pattern_name` (список через запятую). Пример: `total_signals=3, pattern_name="MR_RSI_Reversal, VOL_Spike, PA_Engulfing"` означает, что 3 паттерна дали BUY на одном баре.

## 3. Правила входа

Вход происходит при сигнале BUY, с опциональными фильтрами:

- **Без фильтра (бейзлайн):** Вход по любому сигналу BUY.
- **Фильтр по total_signals:** Вход только если `total_signals >= N` (N=2 или N=3). Сильнее консенсус → меньше, но качественнее сигналы.
- **Фильтр по confidence:** Вход только если `confidence >= C` (C=0.5, 0.7, 0.9). Выше уверенность → меньше сигналов.
- **Комбинированный фильтр:** `total_signals >= 2 AND confidence >= 0.9` (используется в фильтр-бейзлайнах).

Цена входа = open следующего бара (T+1). Если сигнал на последнем доступном баре (нет T+1), сделка пропускается как "untradeable" (не ошибка).

## 4. Правила выхода

Четыре механизма выхода, тестируются в комбинациях:

| Тип выхода | Описание | Параметр |
|---|---|---|
| Stop-loss | Выход если цена падает до entry − stop_atr × ATR(14) | stop_atr ∈ {1.0, 2.0} |
| Take-profit | Выход если цена растёт до entry + take_atr × ATR(14) | take_atr ∈ {1.0, 2.0} |
| Holding expiry | Выход после N баров независимо от цены | holding_bars ∈ {3, 6, 12} |
| Signal exit (sigOn) | Выход по любому противоположному (SELL) сигналу | signal_exit=True, signal_exit_min_total=1 |
| Signal exit strong (sigOn_ts3) | Выход только по противоположному сигналу с total_signals ≥ 3 | signal_exit=True, signal_exit_min_total=3 |
| No signal exit (sigOff) | Игнорировать противоположные сигналы; выход только по stop/take/holding | signal_exit=False |

**Приоритет:** Stop и take проверяются по high/low бара. Если оба сработали на одном баре, stop побеждает (консервативно). Gap-open за уровнем → исполнение по open. Holding expiry и signal exit используют close.

## 5. Матрица бэктеста

Полная матрица тестирует все комбинации параметров выхода:

- **Holding:** {3, 6, 12} баров
- **Stop ATR:** {1.0, 2.0}
- **Take ATR:** {1.0, 2.0}
- **Signal exit:** {sigOn (любой), sigOff (нет)} — и в task-064 sigOn_ts3 (только сильный сигнал)

Итого: 3 × 2 × 2 × 2 = **24 комбинации** (или 30 с фильтр-бейзлайнами, см. ниже).

Каждая комбинация прогоняется на полной вселенной (30 тикеров) или подмножестве (например, SBER/GAZP/VTBR для per-ticker анализа). Результаты сохраняются в `backtest_runs`, `backtest_trades`, `backtest_equity`, `backtest_metrics`.

## 6. Фильтр-бейзлайны

В дополнение к матрице, фильтр-бейзлайны тестируют качество входа:

- **filter_ts2_c0.5:** total_signals ≥ 2 AND confidence ≥ 0.5
- **filter_ts2_c0.7:** total_signals ≥ 2 AND confidence ≥ 0.7
- **filter_ts2_c0.9:** total_signals ≥ 2 AND confidence ≥ 0.9
- **filter_ts3 (task-064/065):** total_signals ≥ 3 (с выходами sigOn/sigOff/sigOn_ts3)

Каждый фильтр-бейзлайн прогоняется с выходами sigOn и sigOff, используя лучшие правила матрицы (h6_s2_t1 или h12_s2_t1). Итого: 3 фильтра × 2 выхода = **6 комбинаций** (или 9 с ts3).

## 7. Бенчмарки

Два бенчмарка для сравнения:

- **Buy&hold:** Для каждой сделки считаем (close_at_exit / close_at_entry − 1) × 100%. Это доходность, если войти в то же время и держать до бара выхода стратегии, без стопов/тейков. Усредняется по всем сделкам группы.
- **Random:** Генерируем len(trades) случайных long входов на случайных барах тех же тикеров, с тем же bars_held, что и у соответствующей реальной сделки. Усреднённая доходность. Проверяет, бьёт ли стратегия случайный вход.

**Примечание:** Buy&hold считается за период удержания стратегии, не за полное 2-летнее окно. Он отвечает на вопрос "добавили ли правила входа/выхода стратегии ценность по сравнению с простым удержанием?"

## 8. Результаты: Короткая история (~1 месяц, 30 тикеров)

Из task-050c smoke (VTBR, 1h, правила по умолчанию):
- n_trades: 261, PF: 0.883, expectancy: −0.052%, win_rate: 36.4%, max_drawdown: 437% (артефакт DD от cum_pnl с нуля; исправлено в task-051 на capital-based DD).

Из task-052 полная матрица (30 тикеров, ~1 месяц, 12 комбинаций правил × sigOn/sigOff + 3 фильтра × sigOn/sigOff = 30 прогонов):
- **Все 30 комбинаций убыточны** (PF < 1, expectancy < 0).
- Лучшая: filter_ts2_c0.9_sigOn (PF 0.952, exp −0.033%, n=1869).
- sigOn систематически лучше sigOff для фильтров (filter_ts2_c0.9: exp −0.033% On vs −0.054% Off).
- Стратегия уступает buy&hold (+0.023%) и random (+0.090%) на сильных сигналах.

## 9. Результаты: Длинная история (2 года, SBER/GAZP/VTBR)

Из task-062 (3 тикера, 2 года, 12 комбинаций правил × sigOn/sigOff + 3 фильтра × sigOn/sigOff = 30 прогонов):
- **Все 30 комбинаций убыточны** (PF < 1, expectancy < 0).
- Лучшая: filter_ts2_c0.9_sigOn (PF 0.800, exp −0.066%, n=310).
- Лучшая в матрице: h6_s2_t1_sigOn (PF 0.744, exp −0.093%, n=1984).
- sigOn лучше sigOff для фильтров; для матрицы sigOff иногда имеет выше PF, но схожий/худший expectancy.
- Стратегия уступает buy&hold и random на сильных сигналах (filter_ts2_c0.9: buy&hold +0.023%, random +0.090%, стратегия −0.066%).

Из task-064 (эксперимент ts≥3, 3 тикера, h6/h12 × sigOn_any/sigOn_ts3/sigOff = 6 прогонов):
- sigOn_any (выход по любому сигналу) лучший: h6_s2_t1_sigOn_any PF 0.787, exp −0.086%.
- sigOn_ts3 (выход только по сильному сигналу) хуже: PF 0.725, exp −0.159%.
- sigOff (без выхода по сигналу) хуже: PF 0.724, exp −0.166%.
- Вывод: выход по любому противоположному сигналу лучше, чем ожидание сильного сигнала или игнорирование сигналов.

## 10. Per-Ticker анализ (Длинная история, ts≥3)

Из task-065 (3 тикера отдельно, ts≥3, h6/h12 × sigOn/sigOff = 12 прогонов):

| Тикер | Лучший PF | Стратегия | Exp % | WR % | Buy&Hold % | Прибыльна? |
|---|---|---|---|---|---|---|
| GAZP | 0.870 | h6_s2_t1_sigOn | −0.058 | 45.8 | −0.104 | Нет |
| VTBR | 0.868 | h12_s2_t1_sigOff | −0.106 | 63.2 | +0.172 | Нет |
| SBER | 0.581 | h6_s2_t1_sigOn | −0.122 | 46.2 | +0.040 | Нет |

- **GAZP:** Лучший PF (0.870), но buy&hold отрицателен (−0.104%). GAZP падал в периоды удержания; стратегия теряет меньше, чем buy&hold. Не edge, просто "теряем меньше на падающем рынке."
- **VTBR:** Buy&hold сильно положителен (+0.172%), но стратегия теряет (−0.08% до −0.12%). Правила выхода (стопы/тейки) режут прибыльное движение. VTBR — единственный тикер, где sigOff конкурентоспособен с sigOn (PF 0.868 vs 0.833).
- **SBER:** Худший PF (0.581). sigOff катастрофичен (PF 0.44, exp −0.30%). Buy&hold чуть положителен (+0.04%) для sigOn, но стратегия теряет −0.12%.

## 11. Ключевые выводы

1. **Ни одна комбинация не прибыльна.** Все 30+ комбинаций матрицы/фильтров имеют PF < 1 и expectancy < 0 после комиссии 0.06%. Rule-based стратегии НЕ имеют edge на MOEX топ-3 (SBER/GAZP/VTBR) за 2 года.

2. **Сигналы несут слабую directional информацию.** Buy&hold на сильных сигналах (ts≥2, conf≥0.9) положителен (+0.023% до +0.172% в зависимости от тикера), значит сигналы слегка предсказывают направление. Но edge меньше транзакционных издержек.

3. **Правила выхода вредят.** Стратегия уступает buy&hold на 0.09–0.29%. Стопы/тейки режут прибыльные движения; holding expiry принуждает к выходу в неудачное время. Лучший выход — "выход по любому противоположному сигналу" (sigOn), но даже он убыточен.

4. **Фильтры улучшают качество, но не спасают.** total_signals≥2 + confidence≥0.9 поднимает PF с ~0.74 (лучший матричный) до ~0.80–0.95, и expectancy с −0.093% до −0.033–0.066%. Всё равно отрицательно.

5. **Высокий win rate — ловушка.** sigOff имеет WR 52–63% (vs sigOn 35–46%), но PF ниже. Широкий стоп (2 ATR) даёт цене двигаться в нашу сторону (высокий WR), но убытки крупные, когда стоп срабатывает (низкий PF). Не оптимизируйте под win rate; оптимизируйте под PF/expectancy.

6. **Комиссия убивает коротко-горизонтные стратегии.** Среднее bars held 2–3. Gross expectancy ~+0.03–0.05% (из buy&hold), комиссия 0.06% round-trip → net отрицательно. Для прибыльности gross edge должен превышать 0.12% (двойная комиссия), чего сигналы не дают.

7. **1d сигналы теперь присутствуют.** Ранее 0 (недостаточно 1d индикаторов: 274 строки). После загрузки 2-летней 1min истории и агрегации в 1d: 213–215 сигналов на тикер. Таймфрейм 1d теперь можно тестировать.

## 12. Выводы и следующие шаги

**Вывод:** Rule-based стратегии (паттерны → сигналы → стоп/тейк/holding) НЕ прибыльны после комиссии на MOEX топ-3 за 2 года. Гипотеза "технические паттерны генерируют tradeable edge" отвергнута для этой реализации, этих тикеров и этого таймфрейма.

**Следующие шаги (варианты):**

- **A. Эксперимент без стопов/тейков:** Чистый вход по сигналу (ts≥3) + holding 24–48 баров, без фиксированных уровней stop/take. VTBR buy&hold +0.17% предполагает, что сигналы имеют directional edge, который стопы/тейки уничтожают. Если чистый holding даст net > 0, проблема в правилах выхода, не в сигналах. Быстрый эксперимент, один скрипт.

- **B. ML (CatBoost/LightGBM):** Перестроить пайплайн на лейблы (доходность вперёд за горизонт), использовать индикаторы как признаки (не бинарные флаги паттернов). ML может найти нелинейные комбинации, которые rule-based пропускает. Требует расширения на 30 тикеров (~1500+ сделок) для избежания переобучения. Большой шаг, без гарантированного edge.

- **C. Расширение на 30 тикеров:** Загрузить 1min свечи для всех 30 тикеров (moex_1min_loader.py, ~5 часов), агрегировать, пересчитать индикаторы/сигналы, перепроверить матрицу на полной вселенной. Подтверждает, держится ли "rule-based мёртв" на полной выборке, не только на 3 тикерах.

- **D. Принять результат:** Задокументировать, что rule-based мёртв на MOEX топ-3 за 2 года. Решить, pivотировать ли (другой рынок, другая частота, фундаментальный подход) или поставить проект на паузу.

**Рекомендуемый порядок:** C (расширение на 30 тикеров) → если подтвердится, что мёртв → A (быстрый тест без стопов/тейков) → если всё равно отрицательно → B (ML) или D (принять).

## 13. Стратегия разворота от уровней (ПРИБЫЛЬНА — заменяет секции 8–12)

> Секции 8–12 выше — ИСТОРИЧЕСКИЕ: rule-based паттерны + ATR стоп/тейк/holding, все убыточны (PF < 1).
> Стратегия разворота от уровней (task-074..080) — другой подход, и она ПРИБЫЛЬНА. Полное описание в `docs/strategy/levels-reversal-strategy.ru.md`.

**Подход:** вход у уровня поддержки 4h только после подтверждения разворота на старшем ТФ (10min свеча закрывается выше зоны поддержки), выход на ближайшем сопротивлении (тейк) или ниже поддержки (стоп), фильтр входа 2:1 прибыль:риск, симуляция на 1min, окно входа 7–19 МСК, остаёмся на ночь/выходные.

**Результат на полной вселенной (task-080e, 28 тикеров, 2 года, проскальзывание 0.05%):**
- **25/28 тикеров PF > 1 (89%)**, медиана PF 1.322, среднее 1.324, все n≥30 (reliable).
- Топ: RUAL 2.07, GMKN 1.91, PIKK 1.74, GAZP 1.71, SIBN 1.65, LKOH 1.62.
- Убыточные: CHMF 0.86, NLMK 0.80 (металлурги), AFKS 0.98 (около нуля).
- Edge реальный на всей вселенной (не специфичен для SBER/GAZP), устойчив к реалистичному проскальзыванию.

**Продакшн-инфраструктура:** `levels_engine.py` (уровни 4h), `levels_backtest.py` (симуляция 1min), `levels_backtest_db.py` (запись в backtest_*), `levels_backtest_jobs.py` (оркестратор матриц + API: POST /api/levels-backtest/run, GET /api/levels-backtest/run/status, shared lock).

**Далее:** walk-forward (out-of-time) валидация по полугодовым окнам для подтверждения, что edge не привязан к рыночному режиму.
