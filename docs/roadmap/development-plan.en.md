## 2. Global Engineering Principles

1. Sandbox only.
   - No production trading.
   - No production tokens in tests.
   - No real order execution until risk controls exist.

2. Task-based development.
   - Every change is done through a task script.
   - Every task produces report.json.
   - The orchestrator reads report.json before proposing the next task.

3. Idempotency.
   - Data loading, aggregation, indicator calculation, signal generation, feature calculation, backtests, and model predictions must be repeatable.
   - Prefer delete-range plus insert, or upsert with unique constraints.

4. No future data leakage.
   - ML features and labels must use only past data.
   - Time-based splits only.
   - Add purge or embargo between train/validation/test windows.

5. Observability.
   - Every important operation must have logs, metrics, and artifacts.
   - Model training must store parameters, metrics, data window, git commit, and model artifact reference.

6. Safety.
   - Do not delete analytical tables without backup.
   - Do not modify trading.signals manually.
   - Do not commit .env, tokens, passwords, certificates.

- Create time-based splits:
  - train;
  - validation;
  - test.
- Add purge and embargo.
- Store dataset metadata.

Suggested database objects:
- ml.labels;
- ml.datasets;
- ml.dataset_splits;
- ml.label_definitions.

Label examples:
- next_1h_return;
- next_4h_return;
- next_1d_return;
- next_1h_return_after_costs;
- next_1d_direction;
- next_1d_class.

Acceptance criteria:

## 13. Agent Decision Rules

For orchestrator and autonomous agents:

1. Always read the latest report.json before proposing a task.
2. If Block A is not complete, prefer stabilization tasks.
3. Do not start model training before feature store and label framework exist.
4. Do not start prediction serving before backtesting validates the model.
5. Do not enable order execution before Block H risk controls exist.
6. If data is unknown, propose a read-only discovery task.
7. If a task fails, propose a fix task with the same task family.
8. Never propose commands that print secrets.
9. Never propose destructive database operations without backup.
10. Prefer small, verifiable tasks over large risky changes.
